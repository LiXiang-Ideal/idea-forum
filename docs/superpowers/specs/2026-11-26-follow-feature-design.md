# 关注功能设计

## 目标与范围

为 IdeaForum 补齐一个完整、可独立交付的用户关注闭环，让读者能够发现作者、查看公开内容、建立关注关系，并在首页阅读所关注作者的新文章。沿用项目现有架构、视觉风格、分页约定和登录安全机制，不复制掘金或其他平台的品牌、代码或页面素材。

本轮包含：

- 公开作者主页，展示公开资料、已发布文章、关注者数和关注中人数。
- 登录用户关注/取消关注作者，并浏览关注者和关注中列表。
- 首页新增“关注”内容流，分页展示当前用户所关注且仍有效的作者发布的文章。
- 首页和文章详情中的作者入口链接到公开作者主页。

本轮不包含站内通知、私信、话题关注、评论回复、管理后台、屏蔽用户或推荐算法。这些功能作为后续独立迭代评估。

## 当前基础

- `sql/001_schema.sql` 已有 `follows` 表，使用 `(follower_id, followee_id)` 组合主键防止重复关系，并禁止用户关注自己；现有索引支持按关注者和被关注者查询。
- 当前没有关注 API、公开用户主页或关注动态流。
- 文章查询行目前返回作者显示名称，不含作者用户名；要提供文章作者主页链接，公开文章响应需包含作者用户名。
- 应用使用 Session Cookie 和 CSRF 保护写操作，服务层采用分页边界限制。

因此本轮复用现有 `follows` 表，不修改初始化 schema，也不新增数据库迁移。

## 架构与数据流

继续使用现有模块化单体分层：

1. Vue 页面通过 `frontend/src/api/community.ts` 调用 REST API。
2. Controller 校验分页参数并从可选或必需的 Spring Security 身份中取得当前用户。
3. 关注服务校验用户有效状态、自关注规则与关注关系，并调用 Mapper。
4. Mapper 通过参数化 SQL 查询用户、关系和已发布文章；分页响应使用现有 `PageResponse` 结构。
5. 前端显示加载、空、错误及未登录状态；写入失败时保留后端错误并允许用户重试。

### API 草案

所有路径使用 `/api/v1` 前缀。

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/profiles/{username}` | 公开 | 返回公开资料、关注计数，以及当前访问者是否关注此用户 |
| `GET` | `/profiles/{username}/articles?page=&size=` | 公开 | 分页返回该用户仍有效的已发布文章 |
| `GET` | `/profiles/{username}/followers?page=&size=` | 公开 | 分页返回关注该用户的有效用户 |
| `GET` | `/profiles/{username}/following?page=&size=` | 公开 | 分页返回该用户关注的有效用户 |
| `PUT` | `/profiles/{username}/follow` | 登录 | 建立关注关系 |
| `DELETE` | `/profiles/{username}/follow` | 登录 | 移除关注关系 |
| `GET` | `/users/me/feed?page=&size=` | 登录 | 分页返回本人关注作者发布的文章 |

公开主页资源使用 `/profiles/{username}`，以保留现有 `/users/me` 私人资料路由并避免两种资源标识冲突。

公开资料仅包含用户名、显示名称、头像 URL、简介、关注数、关注中人数和访问者的关注状态，不返回邮箱等私密字段。不存在或已停用的用户统一按公开资源不存在处理。分页参数遵循现有 profile service 规则，将页码限制为至少 1、每页条数限制为 1–50。

关注和取消关注对重复请求保持幂等；自关注返回明确的客户端错误。关注流只包含有效用户发布的文章，不包含草稿或已停用作者的内容，并按发布时间倒序、文章 ID 倒序。未登录访问关注流返回现有未授权错误；关注按钮对未登录访问者引导登录，登录后返回原页面。

## 前端体验

- 公开主页路由使用稳定用户名标识，不复用仅供本人使用的 `/profile` 页面。
- 主页展示作者资料、关注状态和计数；提供“文章 / 关注者 / 关注中”切换与分页列表。
- 仅登录用户可切换关注状态；本人主页不显示关注自己的操作。
- 首页增加“最新 / 关注”内容流切换；未登录时点击“关注”提示登录，登录后展示关注动态流。
- 首页文章卡片和文章详情作者信息可打开对应主页。
- 空关注流引导用户从文章作者主页开始关注；接口错误提供重试，不以空列表掩盖错误。
- 延续现有 IdeaForum 组件样式、可访问性和移动端布局，不仿制其他产品的独特视觉设计。

## 规则、错误与隐私

- 所有关注写入都要求已认证用户和有效 CSRF token。
- 被关注者必须存在且处于有效状态；禁止自关注。
- 关注关系由数据库唯一约束保证不重复。并发重复关注不得产生重复记录或错误的关注计数；服务层应针对唯一约束以外的数据库异常显式报错。
- 用户主页、用户列表和文章列表只返回公开字段与已发布内容。
- 取消关注后，该作者的文章不再出现在后续关注流查询中。
- 删除或停用用户时沿用现有用户生命周期规则；查询过滤停用用户。本轮不引入新的用户删除策略。
- 遵循统一 API 错误响应，前端显示可操作错误，不做成功形状回退。

## 测试与验收

### 后端

- 关注与取消关注可重复调用，关系计数保持准确。
- 自关注、无效/停用目标用户和未认证写请求被拒绝。
- 主页与关注列表仅返回公开用户字段；文章列表与关注流排除草稿及停用作者。
- 关注流只含当前用户关注作者的文章，并正确分页、按约定排序。
- 运行后端测试套件以覆盖新的服务逻辑和安全边界。

### 前端

- `npm run build` 通过 TypeScript 检查和生产构建。
- 验收作者链接、关注状态切换、未登录引导、关注流空态/错误态以及分页。
- 不添加项目当前不存在的前端测试框架；后端行为测试与前端类型构建作为自动化验证。

### 完成标准

1. 用户可从任意公开文章进入作者主页并查看已发布内容。
2. 已登录用户可以关注或取消关注其他有效用户，自关注不可执行。
3. 关注者/关注中数量和分页名单与持久化关系一致。
4. 登录用户可分页阅读关注作者内容；不关注的作者、草稿和停用作者内容不出现。
5. 匿名用户可浏览公开主页和文章，但关注操作受登录保护。
6. 后端测试和前端生产构建通过。
