# 个人中心关注与粉丝设计

## 目标

让登录用户在个人中心查看自己关注的作者和关注自己的用户，并统一关注相关术语：

- 个人中心增加“我的关注”和“我的粉丝”页签。
- 公开作者页把“关注者”改称“粉丝”，把“关注中”改称“关注”。
- 通过头像、昵称、用户名和简介识别用户，点击名单项可进入对应公开作者主页。

好友关系和私信/聊天是后续独立阶段，本阶段不创建好友或消息数据模型。

## 方案

复用现有 `GET /api/v1/profiles/{username}/followers` 和 `/following` 分页 API。个人中心根据当前登录用户的用户名读取名单，不新增后端接口、数据库表或迁移。名单仅展示 API 已公开的用户资料字段。

新增的个人中心页签沿用现有活动列表状态和分页交互，并覆盖加载中、空列表、错误和重试状态。作者页仅调整显示名称，底层 API 路径和数据字段不变。

## 考虑过的方案

1. 只调整文案并链接到作者主页：改动最小，但不能在个人中心直接查看名单。
2. **推荐：复用现有公开关注 API，增加个人中心分页页签**：完整满足查看名单的需求，不重复后端查询逻辑。
3. 新建仅本人可用的关注名单接口：权限边界更显式，但与现有公开名单功能重复，增加维护成本。

## 验收与测试

- 个人中心可分别浏览登录用户的关注名单和粉丝名单，分页结果与目标用户关系对应。
- 名单中的用户可打开其公开作者主页。
- 作者主页相关页签和计数使用“关注 / 粉丝”称呼。
- 请求失败可见错误和重试入口，空列表显示对应说明。
- 前端 `npm run build` 通过。
